# CodeRabbit analysis: mbcrawfo/SqlSource

## 1. Coverage
- Stack: C# / .NET Roslyn incremental source generator + a CLI tool ("SqlSource.Tool") that describes SQL queries against live PostgreSQL / SQL Server (Npgsql, Dapper, Testcontainers), MSBuild targets, bash scripts, GitHub Actions. The repo is extremely documentation-heavy (specs/plans in `docs/superpowers/`, `docs/tech-debt/TD-*.md`, `docs/manual`, `docs/architecture`, many `AGENTS.md`). The PRs appear to be written by a Claude Code agent (every author reply is signed "Addressed by Claude Code").
- 107 PRs, all with CodeRabbit activity. 121 summary/status issue comments, 191 review objects (only 77 have a body; the other 114 are empty wrappers that GitHub creates for thread replies), 225 inline comments (113 top-level findings + 112 CodeRabbit replies in threads), plus 116 author replies.
- Config: Review profile ASSERTIVE, Plan "Essentials", "Repository UI" config. Median first review about 9 minutes after PR creation (p90 about 17).
- 106 PRs got a walkthrough comment. 85 PR-level comments say "No actionable comments were generated". 54 PRs got a review with a body (38 had one round, 12 two, 2 three, 1 four, 1 five). Actionable counts per review: 1 (39), 2 (11), 3 (5), 4 (7), 5-6 (2). Roughly 12 extra "outside diff range" findings live in review bodies. 28 status comments were rate-limit notices (review limit / usage credits; 14 PRs hit it, e.g. 14, 15, 16, 22, 25, 32, 37, 41, 43, 49, 54, 61, 65, 67). 4 reviews were skipped (e.g. PR12 "no reviewable changes", PR32 over the 150-file limit).
- Severity labels on the 113 inline findings: Minor 85, Trivial 15, Major 13. Nothing "Critical". Every finding carries three tags: category | severity | effort ("Quick win" for nearly all; "Heavy lift" 6; "Low value"/"Poor tradeoff" 5). Hidden marker `cr-indicator-types`: potential_issue 97, nitpick 15, refactor_suggestion 1.
- Categories (CodeRabbit's own): Maintainability & Code Quality 64, Functional Correctness 25, Data Integrity & Integration 10, Stability & Availability 14, Performance & Scalability 8, Security & Privacy 8 (the 113 add up with overlap in the header counts; these are approximate).
- File types of the 113 findings: .md 85 (75%), .cs 23, .targets 2, .sh 2, .sql 1. By area: `docs/superpowers` 31, `src/SqlSource.Tool` 15, `docs/tech-debt` 12, `docs/manual` 11, `docs/architecture` 7, `src/SqlSource` 7, tests about 14.
- Provenance tags at the bottom of comments: "Source: Coding guidelines" 25 (+2 with Learnings), "Linters/SAST tools" 6 (markdownlint MD014/MD029/MD038, LanguageTool, SkillSpector), "Learnings" 2, "Pipeline failures" 1.

## 2. Taxonomy (counts approximate, from the 113 inline findings)
1. **Docs/spec vs. code or vs. other docs inconsistency (about 55).** The dominant class. Stale cross-references, claims that overstate, counts that no longer match. E.g. PR51 TD-0045 "the eighth" when only seven bullets remain; PR60 `src/SqlSource.Tool/AGENTS.md:3` still places shared helpers in the old test project; PR53 D-0003 says phase 8 binds by `name` but the epic specifies `bindName`; PR82 README says provenance fields are excluded though the test compares them; PR101 SQLSRC224/226/... See-links lack the new SQL Server page.
2. **Spec-design correctness (about 20).** Logic holes in design docs. PR94: a SQL Server init command creates the schema in `master` instead of `examples`; Dapper calls need the active transaction; Dapper tests must be version-gated for 2025-only `json`/`vector`. PR25: framework-conditioned PackageReference evaluated under the wrong TFM; stale restore state classified as "plain". PR19: PostgreSQL `scale` can be negative (PG15+). PR21: token-default contract does not match the parser.
3. **Concurrency / lifecycle / cancellation bugs in real code (about 8).** PR41 `Cli.cs`: two termination signals can both pass the `IsCancellationRequested` check, claim the first signal atomically; `SidecarStore` sweep keeps deleting after cancel; `ProcessRunnerTests` uses a timer, use a gate; folder enumerated once per outcome (quadratic). PR50: `_driverLog` assigned before `Build()` can leak/overwrite.
4. **Security / privacy (about 8, 4 accepted).** PR43: allowlist `)`+letters lets `int) AS SELECT 1` close the PREPARE type list (SQL injection into generated statement); PR25: connection string can reach the JSONL log through the describer's log interface; PR94: add canaries for query data to driver-log tests. Rejected: redact driver error messages (PR43, PR50), SkillSpector "confirm before executing" (PR83).
5. **Edge cases / null / bounds in code (about 5).** PR59 `TypeOid` reads `_tokens[2]` for a bare `'x'::` cast (ArgumentOutOfRange, reported as SQLSRC200), missing the `to - from >= 3` guard that `Constant` has; PR79 Dapper handler `new DateTimeOffset(dt)` throws for timestamp infinity in non-UTC zones (Npgsql returns `Kind.Unspecified`); PR89 `Orders.sql` inner join drops users with no orders so "count per user" is wrong (use LEFT JOIN).
6. **Build/MSBuild/CI/config (about 6).** PR75 Web SDK puts `*.json` into `Content`, not `None`, so `DependentUpon` is never applied to `.sql.json` sidecars; PR14 `check-package-install.sh` greps localized compiler output with ASCII quotes (fails in German/Chinese SDK); PR107 pin the SQL Server/PostgreSQL images in a CI recipe; PR104 retry after failed container start must dispose the failed instance and build a new one.
7. **Tests (about 8).** PR67 make test-case dictionaries throw on duplicate keys (`{ "name", v }` instead of indexer), assert the script is fully consumed; PR21 allocation budget lacks the keep-comments path; PR101 pass the caller's cancellation token through the open path so a regression is detectable; PR76 require `Unchanged` for a probe.
8. **Performance (about 5).** PR21 record before/after timing for lexer hot-path change in the PR description; PR41 quadratic folder enumeration; PR36 `string.Join` allocation claim is runtime dependent.
9. **Style / wording / markdown (about 15).** Sentence fragments, closing a code span (PR30, PR67, PR90), `AGENTS.md` length (PR50, PR89), unclear intro (PR71). Often from markdownlint / LanguageTool.
10. **Not seen at all:** dependency/vulnerability findings, naming nits in code, i18n, API-misuse in production code beyond the above.

## 3. Highest-value findings (accepted and fixed, many with a failing test added)
1. PR43 spec: declared type text interpolated into `PREPARE` allows `int) AS SELECT 1` (allowlist too loose). Author replaced it with a real type-name grammar and added a second defence (line break before `AS`).
2. PR41 `Cli.cs`: simultaneous SIGTERM+SIGHUP both pass the cancellation check. Fixed with `Interlocked.Increment`; test `Interrupt_SeveralAtOnce_OnlyOneIsTheFirst` "failed against the old check within milliseconds".
3. PR41 `SidecarStore`: whole-project sweep keeps deleting files after cancellation. Fixed; test failed before.
4. PR79 Dapper `DateTimeOffset` handler throws on `infinity`/`-infinity` outside UTC. Author reproduced under TZ=Asia/Tokyo; test added.
5. PR59 `PlanExpression.TypeOid` out-of-range read on `'x'::`. Guard added, 2 test rows added (first threw before fix).
6. PR25 connection string reaching the describer's log. Author restructured: log no longer part of `OpenRequest`; a `SessionRunLog` redacts the connection value in every string at any depth.
7. PR74 silently choosing the Npgsql 10 type map when no Npgsql reference exists (`date` maps to `DateOnly` but Npgsql 8/9 return `DateTime`). Fixed: only types that box identically on 8/9/10 map without a driver; others need an override or SQLSRC249.
8. PR94 SQL Server init applied schema to `master` not `examples`; Dapper needs the active transaction; Dapper tests gate by major version.
9. PR75 Web SDK `Content` items missed `DependentUpon` (CodeRabbit searched docs; author verified in a Web SDK project).
10. PR89 `Orders.sql` inner join vs promised count per user (the generated example's sidecar re-recorded).
11. PR25 multi-target consumers: `-getItem:PackageReference` also needed; author found the problem "wider than a conditioned reference" after restoring a multi-target project.
12. PR14 localized compiler output breaks apostrophe matching (author confirmed with `DOTNET_CLI_UI_LANGUAGE=de`/`zh-CN`).
13. PR104 failed Testcontainers start retried on a disposed/failed instance (design of retry).
14. PR28 inherited `Configuration`/`Platform` env vars leak into test project evaluation (partially adopted).
15. PR67 case dictionaries with duplicate keys silently overwriting tests (indexer vs `Add`); 11 rows converted.

## 4. Noise
- Author disposition of 113 top-level findings: 96 fixed, 1 partial, 16 declined (14%). Every thread got a reply (the repo's AGENTS.md says deferred minor feedback is not allowed, which inflates acceptance; it also means fixes are sometimes cosmetic).
- Declined ones: PR13 (CodeRabbit claimed CS0617, compiler gives CS0246; author ran Roslyn 4.8.0 and 5.9.0, CR then withdrew), PR61 (line limit applied to the wrong file), PR62 (`CREATE TABLE IF NOT EXISTS` race, but collection runs sequentially by design), PR78 (reserved keyword as warning id: author ran csc, no CS1072), PR2/PR30/PR76 (asked to update specs/plans, but `docs/superpowers/AGENTS.md` says those are records of intent; **it raised this class three times** even after Learnings were stored), PR50 x3 (redact exception message; spec decision; AGENTS.md size), PR43 (redact driver error: tool cannot parse connection strings), PR83 (confirmation gate on a skill, from SkillSpector), PR71 (check root-level paths: about 80 false positives), PR82, PR89, PR41 `ProcessRunner` (wait for descendants).
- CodeRabbit conceded 32 times in follow-up replies ("you're right", "I withdraw this finding", "misapplied") or accepted explanations, and recorded 28 "Learnings added" from them.
- Lower-value patterns: markdownlint/LanguageTool items flagged "Unverified finding" (PR25 MD038, PR65 MD014, PR83 MD029, PR78 grammar, PR53 duplicate period); "Keep this AGENTS.md concise"; wording clarifications ("Clarify the introduction"); trivial nits tagged "Low value"/"Poor tradeoff". Effort tag is a decent noise filter: all 5 Low value/Poor tradeoff findings were nitpicks, 4 of 5 declined.
- Rough signal-to-noise: of 113, about 25-30 are real defects or real design gaps (security 3, concurrency 5, edge case 3-4, build/CI 4, spec-logic 10+); about 55 are legitimate doc-accuracy fixes (low stakes but true); about 25 are style/wording; 16 were wrong or declined. So roughly 25% high value, 50% useful hygiene, 25% noise. Real production-code bugs are rare: 23 of 113 findings touch .cs.

## 5. Behaviors beyond inline comments
- **Walkthrough/summary comment** (one per PR, edited in place on every push): "Review in Change Stack" link, "Recent review info" (profile, plan, run id, commit range reviewed, files selected, "No actionable comments"), table of changes by layer/file, **Priority** (Low 48 / Normal 52 / High 1) and **Merge Risk** with a one-sentence rationale (Minimal 51, Low 11, Moderate 1: PR104, "should be corrected before merge to avoid exposing connection details"), **Pre-merge checks** table (Description/Title/Linked issues/Out-of-scope; always passed here), "Possibly related PRs", and an Autofix checkbox. No sequence diagrams, no poem, no effort estimate in this repo's output.
- **Verification before commenting**: 30 of 113 findings embed "Supported by static analysis" with the shell it ran (`rg`, `nl -ba file | sed -n`, `git diff base head`, `git show`) against a checkout; 6 ran web queries; 16 cite upstream docs/source (Npgsql source on raw.githubusercontent, learn.microsoft.com, postgresql.org). Findings that it could not confirm are labelled "Unverified finding: Verification ran but could not confirm this finding" and shown in the review body rather than inline.
- **Reads the repo's AGENTS.md** and cites it: "As per coding guidelines, ..." (22 findings; "Source: Coding guidelines" footer 27). It enforces repo rules (docs kept current, test project placement, line limits, "tech-debt item states measurements").
- **Thread conversations**: CodeRabbit answers every author reply (112 replies): verifies the new text/code ("Confirmed in the supplied file: ... This addresses the finding"), marks "Review thread resolved", appends "Addressed in commit abc123" or "Confirmed as addressed by @user" to its original comment, or concedes and "withdraws the finding", storing a Learning.
- **Commands used by the author**: `@coderabbitai review` (PR64, 77, 98, 106), `pause`/`resume` (PR94, 95, 98), and replying in the PR timeline to findings that have no thread ("outside diff", "unverified" ones; 14 such replies).

### Follow-up pushes (the thing we care about)
- Each push triggers an **incremental** review: all 77 review bodies say "Reviewing files that changed from the base of the PR and between <prev reviewed sha> and <new sha>"; the first review covers base..head. E.g. PR90: round 1 covered 12 files, later rounds covered 2, 2, and 4 files; PR101: `d920cb0..cdee7c3` then `cdee7c3..ee566a5`.
- Later rounds produce typically 1 finding each and mostly on the text just edited (often a flaw in the fix, e.g. PR78 round 2 on the same sentence; PR21's re-measured baseline). Median 1 round per PR, so most PRs converge in one pass.
- It keeps the prior threads alive: replies re-check the diff since the comment, then resolve. Resolved comments get "Addressed in commit(s) X to Y". It does not re-raise a fixed finding. It does however re-raise the same "update the spec to match code" class across PRs despite stored learnings.
- The author can stop it: "Reviews paused" with "Last reviewed commit / Latest commit, not reviewed", and autoreview resumes on `resume`. Summary comment always states the last reviewed commit and (new) a "Merge Risk · up to `sha`" label so staleness is visible.
- Rate limiting: after the review quota (about 5/hour on Essentials, "2 included reviews remain" footer) it posts a "Review limit reached" notice; no incremental review happens until retried.
- Empty-body "COMMENTED" reviews with no inline comments are just wrappers for thread replies.

## 6. How findings are phrased
- Fixed structure: hidden marker line; `**category** | **severity** | **effort**`; bold imperative title ("Claim the first termination signal atomically."); 2-4 sentence explanation naming the trigger, failure, and consequence ("Trigger: ... Failure: ... Contract: ..." bullets in PR59); a fixed "Proposed fix" / "Suggested fix" diff (58 of 113 contain a diff, many a committable `suggestion` block); citation to upstream source when relevant; "As per coding guidelines" quote; "Affects N files" consolidation of duplicates across files; line ranges in the review body for outside-diff comments.
- It states whether the bug is reachable today (PR59: "the walk cannot reach the throw now. A direct caller ... would"), which helps triage. It tags low-value items itself ("Low value", "Poor tradeoff").
- Findings are scoped to the diff plus nearby unchanged lines; "outside diff range" ones appear only in the review body.

## 7. Surprises / repo-specific
- 75% of findings are on markdown. The most productive use was cross-document consistency in a repo of linked specs, TD items and manuals, something a generic local review rarely does.
- The AI-authored PR / AI-reviewer loop converges quickly (author replies cite a commit SHA and a test that "failed before the fix" for about 10 accepted findings), and the author often tests CodeRabbit's claim empirically before accepting (csc, Roslyn 4.8/5.9, German SDK, Asia/Tokyo TZ). A local skill should likewise have the reviewer produce a reproducible check for each claim.
- Learnings are keyed to repo rules and AGENTS.md; a local skill should load `AGENTS.md` and nested `AGENTS.md` files and cite rule + file.
- Merge Risk and Priority summary is an easy-to-reproduce, useful triage artifact.
- No findings on dependencies, secrets scanning, or style of .cs code; those are probably handled by the repo's own analyzers/pre-commit.
