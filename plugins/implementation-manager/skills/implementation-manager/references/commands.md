# The run script's commands

`run.py` is the shorthand SKILL.md defines ("The run script"). `<run>`, the absolute run folder, always comes right after the command (for `item`, after its subcommand). A refused command exits 1 with one line on stderr and changes nothing.

| Command | Does |
|---|---|
| `init <run> --repo <owner/repo> --base <base> --method <merge\|squash\|rebase> [--wip N]` | Creates the run folder. The queue is `serial` (one PR in flight) unless the owner asks for `--queue parallel`. |
| `unit <run> <name> [--prereq U ...] [--after U ... \| --after none] [--title T] [--branch B] [--worktree P] [--specs] [--spec P]` | Adds a unit (letters, digits, `-` and `_`), or updates the fields given. `--after` units must merge first, but don't gate the start; a stopped one counts as merged, and `--after none` clears the list. A unit can't both need and merge after the same unit, and cycles are refused. Each `--after` unit must already exist. Giving the slot holder an `--after` unit not yet merged frees the slot. `--title` is shown beside the name in `status`. `--spec` is the path of the unit's spec, which its brief names. A `--worktree` different from the stored one (compared normalized) starts a new session generation: the new child numbers its items from `Q1` again, and the unit's open items from the old session are dropped, with `dropped <id>` printed for each. |
| `set <run> wip <N\|none>`, `set <run> queue <serial\|parallel>` | The owner's changes mid-run. In parallel mode it prints `queued <unit> <sha>` for each request still queued. |
| `set <run> manager <local_id>` | Records this session's id, which every brief names. |
| `open-ready <run>` | Opens every gate that may open now (prerequisites merged, within the WIP limit) and prints their names. A unit that an open unit merges after, and every unit that one needs or merges after in turn (none through a stopped unit), may open past the WIP limit, in the same call. |
| `open <run> <unit>`, `stop <run> <unit> <reason>` | Opens one gate; stops a unit for good (it never opens, gets `go` or queues again, and gives up the slot). It drops the unit's items and prints `dropped <id>` for each. |
| `go <run> <unit> <sha>` | Allows the push. It refuses a held unit. In serial mode it also gives the unit the slot, and refuses while another unit holds it or is first in the queue, or while the unit merges after a unit not yet merged. |
| `queue <run> <unit> <sha>` | Holds a covered request until the slot frees; the watcher then reports `NEXT`. A queued unit whose `--after` units haven't merged is skipped at the head, so the next one is served. It refuses a held unit. The slot holder can be queued only when it merges after a unit not yet merged; it gives up the slot. |
| `redo <run> <unit> <sha> <reasons>` | Refuses the push with one line of reasons. A slot holder gives up the slot; an earlier `go` not yet pushed is spent. |
| `hold <run> <unit> <reason>` | Holds the unit's merge until `release`, `merged`, `closed` or `stop`: no READY or REMIND, no STALLED unless the reason starts with `answer sent:`, and `go` and `queue` refuse it. It frees the slot if the unit holds it, drops its queue entry, and answers each waiting request (unanswered or queued) `redo <sha> held`. A done unit can't be held. |
| `release <run> <unit>` | Lifts the hold and restarts the stall clock; a PR reported `READY` before the hold is reported again. |
| `yield <run> <unit> <reason>` | The slot holder gives up the slot. Its PR stays open; it returns to the front of the queue when it asks again. A `go` it has not pushed stays outstanding: its old head is not reported ready. The integration unit's `go` stops holding unit merges, though (see the `STUCK … no-push` row in events.md). |
| `merged <run> <unit> <pr> [--more]`, `closed <run> <unit> <pr>` | Records a merge (`--more`: a part k of N with k < N) or a close, and frees the slot. |
| `status <run>` | The tracker and every line under "needs the manager". Its `- items:` line is `current <id> (<ref>) <summary> · <N> more: <unit> ×<n>, …` (or `· nothing more`, or `none`); `- parked:` appears when anything is parked; `forward due <unit> <ids>` is listed under "needs the manager". Its last line may be `- context: <N>k`, this session's context size, ending `, compact due` when the run is quiet and it is time to ask the owner to compact (SKILL.md). |
| `compact-asked <run>` | Records the context size now as the point the owner was last asked to compact. |
| `clear-bad <run>` | Forgets the bad request lines `status` lists, once you have handled them. |
| `item add <run> <unit> [--ref Q<n>] --kind <question\|finding\|command\|decision> --blocks <yes\|no> [--depends Q<n> ...] --summary S --body-file P`, or `item add <run> --run-wide --kind decision --blocks no --summary S --body-file P` | Files an item for the owner (owner-queue.md). Prints `current <header>`, `queued <id> for <unit>, <N> waiting`, or `parked <id> with <parent>` (it depends on a parked item). Refuses a stopped unit, a `--ref` already used in the unit's current session generation (naming the item that has it), a `--depends` ref not in it, `--depends` without `--ref`, and a ref on a `decision`. |
| `item current <run>` | The current item's header line, a blank line and its body; `none` when nothing is current (also when only parked items remain). The header is `<id>[ (<ref>)] · <unit\|run> · <kind> · blocks merge: yes\|no[ · depends on: <ids>] · <summary>`. |
| `item done <run> <id> [--answer-file P]` | Closes the current item, or a queued or parked one, storing the owner's answer; every kind but `decision` needs `--answer-file`. Prints the new current header or `none`, then any `forward due <unit> <ids>` lines. |
| `item park <run> <id> <note...> [--with ID ...]` | Parks the item with the owner's note, and with it its marked dependents and the `--with` items. Prints `parked <id>` for each, the new current header or `none`, then any `forward due` lines. |
| `item unpark <run> <id> [--queue]` | Makes a parked item current at once and prints its header; the item it displaces comes next once the unit has nothing queued, and what was parked with it rejoins the queue. `--queue`: back in the queue at its old place instead; prints `queued <id>`, or `current <header>` if it became current. |
| `item forwarded <run> <unit>` | Marks the unit's answered items forwarded, once you have sent them; prints `forwarded <ids>`. Refused unless a `forward due` line (from `done`, `park` or `status`) lists the unit. |
| `item drop <run> <id> <reason...>` | Drops an item that no longer matters. Prints nothing: run `run.py status <run>` after it (and after `stop`) for the new current item and any `forward due`. |
| `item list <run>` | One line per open item: `current …`, `queued …` in display order, `parked … · <note> since HH:MM`, `answered … (not forwarded)`; `none`. |
| `check <run> <unit>` | One readiness check of the unit's PR now: `READY <pr> <sha>`, `NOT-READY …`, `MERGED <pr>`, `CLOSED <pr>` or `ERROR …`. |
| `wait <run> --full [--stall-hours N]` | Blocks until one event, prints it, exits 0. Always with `run_in_background`, and always with `--full`, which then prints: for `REQUEST`, `PENDING`, `NEXT`, `READY` and `REMIND`, `verdict <sha> <JSON>` (branch-review's `rs covered` output: `covered`, `reasons`, `branch`, …) or `verdict <sha> unavailable: <reason>`; for a `STUCK` event, `pushes: <the unit's last pushes.log line>` and `requests: <its last requests.log line>`; then an empty line and the `status` block. |
| `check-cmd <run> --rs <path> --state-dir <dir>` | Records branch-review's `rs` script and state folder, for the verdict `wait --full` prints. Refused when the path is not a file. A verdict `unavailable: rs not found: <path>` means branch-review was updated: record the new paths. |
| `brief <run> <unit> [--extra-file P] [--no-gate] [--designed]` | Writes the unit's child prompt to `<run>/briefs/<unit>.md` from the plugin's templates and prints that path. Part 6 gets `<run>/facts.md`, then the `--extra-file` text. `--no-gate` leaves out the gate (part 2); `--designed` adds the paragraph for a unit the owner designs with the child. The integration unit gets the integration child's prompt, and in integration mode the other units get the mode's changes. Refused without a manager id (`set manager`), a unit without a `--spec`, or a placeholder the run cannot fill. |
| `prune <run> --days D` | Removes this repo's run folders beside `<run>` untouched for D days, never `<run>`, which need not exist yet. Prints `{removed, skipped, errors}` as JSON; exits 1 when `errors` is not empty. |

Integration-branch mode only (see "Integration-branch mode" in setup.md):

| Command | Does |
|---|---|
| `init <run> … --integration integration/<slug> --final-merge <manager\|owner> --feature-review <yes\|no>` | Turns the mode on. All three options or none; there is no default for either choice. Refused with `--method rebase`. |
| `unit <run> <name> --integration` | Makes the unit the run's one integration unit. Its branch is the integration branch and may be nothing else; it has no `--prereq` or `--after`, and no unit may name it in either. `open-ready` opens its gate at once, outside the WIP limit. |
| `set <run> final-merge <manager\|owner>`, `set <run> feature-review <yes\|no>` | The owner's changes to the two choices. Refused once the final gate has opened. |
| `synced <run> <unit> <sha>` | The integration unit pushed its `go` straight to the integration branch: clears the `go` and frees the slot if it holds it. A unit PR reported `READY` while the sync was in flight is reported `READY` again. Refuses another unit, or a sha that is not its outstanding `go`. |
| (request line) `<unit> syncing <sha> <branch>` | Written by the integration child, not you, when its base merge conflicts. It holds unit merges (`integration sync in flight`, also for a line no `wait` has read yet) until its next push request, a `redo`, `stop`, `merged` or `closed`. `wait` reports `STUCK <unit> - syncing` once if no push request follows within an hour. From any other unit it is a bad line. |
| `open-ready <run>` | Also prints `<unit> final review` or `<unit> final no-review` (and logs it to `gates.log`), once, when every other unit is done or stopped and at least one is done. |
| `check <run> <unit>` | Also prints `NOT-READY <pr> head=<sha7> blocked: <reason>` while an integration block applies or the PR targets the wrong base (`targets <ref>, not <expected>`), and `FINAL-READY <pr> <sha>` for the final PR of an owner-merges run. |
